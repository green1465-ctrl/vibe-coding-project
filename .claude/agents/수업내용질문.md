# 부트캠프 수업 내용 정리 (질문용 컨텍스트)

> 자료 출처: 로컬 `OneDrive/바탕 화면/부트캠프/` 아래의 스크린샷·메모(.txt/.md) 모음을 주차별로 정리.
> 이미지는 파일명이 한국어 설명문 형태라 그 캡션을 기반으로 내용을 통합.
> 질문할 때 "이 문서 컨텍스트로 답해줘"라고 쓰면, Claude가 내가 배운 흐름을 알고 답변 가능.

## 1주차 — Claude Code & Git

### 1-1. Claude Code 환경 세팅

- **Cursor / Claude Code / Git 설치 여부 확인**을 Claude에게 먼저 물어본다.
- `Ctrl+Shift+P` → **Open User Settings (JSON)** 검색해서 아래를 넣으면 md 파일이 미리보기 스타일로 보임.
  ```json
  {
      "workbench.editorAssociations": {
          "*.md": "vscode.markdown.preview.editor"
      }
  }
  ```
- **VScode = Visual Studio Code**: 마이크로소프트 무료 코드 메모장. JSON 설정 파일이 동작 규칙. 비유: VScode = 집, JSON = 집안 규칙장부.
- **모델 설정**: 에이전트 작업 시 화면에서 모델 선택 가능. **Opus는 Sonnet보다 토큰을 약 10배 더 씀** → 가벼운 작업은 Sonnet.
- **프롬프트 팁**
  - "딱 이 파일만 참고해서"라고 지정 → 토큰 절약.
  - 경로(path)를 정확히 지정 → Claude가 다른 곳을 안 뒤져서 토큰 절약.

### 1-2. 에이전트(Agent)

- **에이전트 만들기**: 새 Claude 창에서 `/agents` → 폴더 설정 선택.
- **Generate with Claude (추천)** vs **Manual configuration**

| 항목 | Generate with Claude | Manual configuration |
|------|----------------------|----------------------|
| 방법 | AI 자동 생성 (설명 입력) | 직접 JSON/YAML 편집 |
| 난이도 | 쉽고 초보자용 | 전문가용 |
| 유연성 | 기본 자동화 | 완전 커스터마이징 |

- **도구 그룹 (All tools / Read-only / Edit / Execution / MCP / Other)**: 기본은 All tools. 보안 필요 시 Read-only.
- **메모리 스코프**
  - `Project scope` (`.claude/agent-memory/`) ← 추천, 프로젝트 전용
  - `User scope` (`~/.claude/agent-memory/`) — 모든 프로젝트 공유
  - `Local scope` (`.claude/agent-memory-local/`) — Git 무시, 민감 데이터
  - `None` — 매번 초기화
- **프로젝트 vs 퍼스널 에이전트**: 슬래시 에이전트 저장 시 "프로젝트(`.claude/agents/`)"는 프로젝트 전용, "퍼스널(`~/.claude/agents/`)"은 전역.
- **md 파일은 `.claude/agents/` 아래 있어야** Claude가 에이전트로 인식. 새 에이전트를 추가하면 **반드시 Claude Code를 껐다(`Ctrl+C`) 다시 켜야** 인식됨.
- 에이전트 호출: 채팅창에서 `@` 입력 → `.claude/agents/...` 경로 선택.
- **에이전트는 메모리가 있고, 스킬은 메모리가 없다** (5주차 보강).

### 1-3. 첫 에이전트 (레시피 / K-드라마)

1. `recipe-agent.md` 생성 → 껐다 켜기 → `/agents`로 확인.
2. 채팅에서 `@recipe-agent` + "굴소스 볶음밥 레시피 만들어줘" → 결과 생성.
3. 이미지 생성 시 → **나노바나나** API 키 필요.
4. `K-drama expert.md`도 동일 방식.
5. `.claude` 아래 "다이어리" 폴더 만들고 오늘 날짜 md 다이어리 작성.
6. `@K-drama-expert` + 다이어리 md 경로 + "막장드라마로 써줘" → md 저장.

### 1-4. 메모리 & 뉴스 수집 에이전트

- `news-collector.md`로 뉴스 자동 생성.
- 파일 생성 절차: 에이전트 폴더 우클릭 → New → `이름.md` → 내용 붙여넣고 **꼭 저장**.

### 1-5. Git & GitHub

- **Git**: 내 컴퓨터 안의 타임라인(세이브포인트). **인터넷 필요 없음.**
- **GitHub**: Git 커밋을 **인터넷에 올려 백업/공유**. Git과는 별개의 서비스.
- **초기화**: "이 폴더를 git으로 관리할게" 선언. Claude에 "git 초기화해줘"로도 됨.
- **커밋**: Claude에 "지금 변경사항 commit 해줘".
- VSCode 왼쪽 git 패널 → 연결 아이콘 → 초기화 → 좌하단 `Initial commit` 표시.
- **이전 상태로 되돌리기**
  - git 패널에서 커밋 우클릭 → **Checkout (detached)**.
  - 또는 Claude에 "첫 번째 커밋으로 돌아가줘".
  - `Discard all changes` — 변경 원복.
  - `/rewind` — 이전 버전 복구.
- **깃 저장 위치**: 프로젝트 루트의 `.git/`. `objects/`(실제 커밋·파일), `refs/`(브랜치/태그), `HEAD`, `config`, `logs/`.
- **GitHub 푸시**
  - "GitHub에 푸시해줘" → Claude가 계정·로그인·CLI 상태부터 확인.
  - **CLI 로그인 안 될 때**: 별도 cmd창에서 `gh auth login` → yes → `Login with a web browser` → 코드 복사해 GitHub에 붙여넣고 Continue.
  - **리포지토리 = 코드 저장소**. 공개(public)로 만들고 push.
- 파일 지우고 commit하면 "md 파일 삭제"로 changes에 표시 → 다시 커밋 가능.

## 2주차 — HTML/CSS/JS + React 에이전트 (`single-react-dev`)

### 2-1. 언어 기본기

- **HTML** — 웹페이지 뼈대 마크업. 계산·로직 X, 구조만. `<h1>안녕!</h1>`
- **CSS** — HTML에 색·크기·배치를 입히는 언어. Cascading 특성으로 우선순위 충돌 자주 발생(같은 속성 두 번 쓰면 나중 게 이김).
- **JavaScript** — 움직임·상호작용. 클릭·통신·애니메이션·폼 검증. Node.js 덕분에 서버에서도 동작.
- **브라우저** — HTML/CSS/JS를 해석해 보여주는 프로그램(크롬 등).

### 2-2. `single-react-dev` 에이전트 설치

- `single-react-dev.md`를 `.claude/agents/`에 넣고 Claude 재시작.
- 채팅에서 `@single-react-dev`로 호출.

### 2-3. 폴더/파일 만드는 흐름 (공통 패턴)

1. `week-2` 아래 새 폴더 (예: "나이계산기").
2. 그 폴더에 `index.html` 파일 생성. **확장자가 중요**.
3. 파일 경로 우클릭 → **Copy Path**.
4. 채팅창에 `@single-react-dev` + 폴더 경로 + 명령. 예: "이 폴더에 나이계산기 만들어줘. CSS도 넣어줘."
5. 만들어지면 좌측 패널 우클릭 → **Reveal in File Explorer** → 크롬으로 열기.

### 2-4. 프롬프트 입력 순서 (UI → 서버 → 연결, 핵심 패턴)

```
1. @single-react-dev
   └ my-pokemon-docs 여기에 간단하게 포켓몬 검색 UI 그려줘
     포켓몬 5마리 너가 넣어줘

2. @single-server-specialist
   └ my-pokemon-docs 여기에 포켓몬 데이터를 api로 뿌려주는 서버 만들어줘

3. index.html에서 이 서버 api를 사용해줘 (하드코딩된 포켓몬 말고)
```

### 2-5. 개발자 도구(F12)

- 크롬 우상단 → Developer Tools, 또는 `F12`.
- **Console** — 에러가 어디서 났는지 표시. 에러는 **그대로 복사해서 Claude에 붙여넣기**.
- **Network** — 서버와의 통신. URL이 `file://`인지 `http(s)://`인지 확인 가능.
  - 서버 없이 index.html을 직접 열면 `file://`.
  - 로컬호스트(서버)로 열면 `http://`.
- "스킬 써줘" — 특정 스킬 호출도 가능.

## 3주차 — 서버 / Node.js / Express / API

### 3-1. 왜 서버가 필요한가

- 로그인·회원가입·**데이터베이스**·**결제**·**AI API 키 보호**.
- index.html만 있으면 인터넷 불필요(그냥 파일 열기).
- 서버에 올리고 도메인 붙이면 다른 사람이 접속 가능 = **static 파일 서빙**.
- 서버의 역할 2가지
  1. **static files 서빙** (html/css/img/font 등)
  2. **API 서빙** (데이터·기능)
- **file:// vs http:// 차이**: 같은 html이라도 Network 탭의 URL이 다르게 표시 = 서버 유무의 차이.
- **외부 서버에 요청 → API 경로를 통해 응답** → 그 데이터를 사용. (API = 데이터의 입출구)

### 3-2. Node.js / Express / npm

- 서버는 **JavaScript(Node.js)** 로. 프론트도 JS, 서버도 JS — 풀스택을 한 언어로.
- "간단한 node 서버 만들어줘" = Node.js로 서버 구성해달라는 뜻.
- **npm = Node Package Manager**.
- **package.json** — 외부 오픈소스 패키지의 **명세서**. 예: 비밀번호 암호화 알고리즘을 직접 짜지 않고 패키지를 가져다 씀.
- **express**: Node.js 표준처럼 쓰이는 서버 프레임워크.
  - 기본 Node.js http보다 코드 짧고, 정적파일 서빙 간단(폴더명만), 라우트 분리 깔끔.
  - express 쓰면 `package.json` 생성 → 외부 패키지이므로 `npm install` 필요.
  - "node.js 서버를 express로 바꾸고 변경사항 md로 정리해줘" 요청하면 변경 내역 정리됨.

### 3-3. 기본적인 Node.js 서버 코드

```js
const http = require('http');

http.createServer((req, res) => {
  res.write('Hello from 서버 JS!');
  res.end();
}).listen(3000);
```

- `const http = require('http')` — Node.js 내장 HTTP 모듈 불러오기. http는 브라우저-서버 통신 규칙.
- `createServer(...).listen(3000)` — 3000 포트에 서버 띄우기.
- `readFile` 패턴 — 디렉토리 파일을 읽고 에러 없으면 `res`로 응답. 응답 본문은 Network 탭에서 확인 가능.

### 3-4. `single-server-specialist` 에이전트 흐름

1. `.claude/agents/`에 `single-server-specialist.md` 넣고 Claude 재시작.
2. 프롬프트 예: **"간단한 node 서버 만들어줘. static file 서빙 예시와 hello API 예시도."**
3. 결과: `server.js` + `public/index.html`.
   - **public 폴더가 생기는 이유**: 공개 이미지/폰트 등을 모아두고 서버가 static으로 서빙.
   - public 바깥 경로 접근을 막기 위한 **경로 검증 보안 코드** 포함.
4. 서버 실행은 **쉘에서 직접**: `cd 폴더` → `ls -la`로 확인 → `node server.js` → `http://localhost:3000` 접속.

### 3-5. localhost / IP / 같은 와이파이

- **localhost = 127.0.0.1** = "내 컴퓨터" 축약.
- 자기 컴퓨터 서버 접속 가장 빠른 방법: `http://localhost`.
- **같은 와이파이의 다른 기기(폰 등)에서 접속**: 내 컴퓨터의 **내부 IP** 사용.
  - `192.x.x.x` = 내부 IP (같은 와이파이 내).
  - `137/17/67`로 시작 = 외부 IP (외부에서 인식).
  - "같은 와이파이 사람들이 들어오게 해줘"라고 Claude에 부탁.
- **IP ↔ 도메인**: 도메인을 붙이면 IP가 사람이 읽기 쉬운 이름으로 바뀜.
- 비유: 프린터 설정의 내부 네트워크 IP와 동일 개념.
- **포트**: localhost는 하나, 포트는 여러 개(3000/4000…). 여러 Node 서버는 포트만 다르게.

### 3-6. GET vs POST

```
GET : "이미 준비된 파일 줘!"   → 즉시 응답   (static / 열린 API)
POST: "새로 계산해서 만들어줘!" → 처리시간 필요 (결제·가입 등)

GET  /users  → DB에서 0.1초만에 조회
POST /order  → 결제처리 + 재고체크 + 이메일발송 (2~3초)

❌ GET  /login?email=...&pw=...   ← URL에 비번 노출!
✅ POST /login                     ← body에 숨김
```

- GET — static 또는 열린 API에서 응답을 가져오는 역할.
- POST — 시간/사양/인증이 필요할 때. 한 번에 처리되기도, 중간 검증이 끼기도.

## 3주차 프로젝트 ① — 포켓몬 도감 (하드코딩 → 서버 → 외부 API)

### 왜 서버에 하드코딩부터 시작하나
- 베스트는 DB에 저장. 아직 DB 안 배웠으니 일단 `server.js`에 하드코딩.
- 데이터를 **index.html이 아니라 서버 쪽에** 두는 연습이 핵심.

### 흐름
1. **프론트**: `@single-react-dev`로 "포켓몬 5마리 도감 UI". 이때 데이터는 index.html 하드코딩, Network URL은 `file`.
2. **서버**: `@single-server-specialist`로 "이 폴더에 포켓몬 데이터를 API로 뿌려주는 서버". → `server.js` + `/api/pokemons`.
   - 데이터가 서버에만 존재. API 호출 안 하면 화면에 아무것도 안 뜸. 결제/주문 데이터를 서버에 숨기는 원리와 동일.
3. **연결**: "index.html에서 이 서버 api를 사용해줘. 하드코딩된 포켓몬 말고." → `fetch('/api/pokemons')`로 서버에서 받아 렌더링.
4. **npm install** → `node server.js` → `http://localhost:3000` 접속.

### 왜 index.html을 직접 열면 안 보일까
- 데이터가 서버 API에만 있는데, `file://`로 열면 브라우저가 서버를 인식 못 함(보안 정책).
- 반드시 `http://localhost:3000`으로 열어야 `fetch`가 동작.

### CORS
- `file://`로 열면 자기 서버를 못 알아보고 **CORS 에러** → Node.js 기본 보안.
- **PokeAPI**는 CORS가 열려 있어 어떤 방식으로든 받아옴.
- **CORS 본질**: 서버 API를 어떤 클라이언트가 쓸 수 있는지 정하는 규칙. 서버는 **보안·권한**을 다룸. 정책 넓히면 공공 API, 좁히면 사내 API.

### PokeAPI로 확장
- 5마리 → 100/1000마리는 직접 넣기 힘들고, 데이터 정확성·신규 반영도 수동.
- **PokeAPI** — 자동 업데이트, 대량 데이터.
- 프롬프트: "PokeAPI 이용해서 포켓몬 데이터 검색과 연결해줘."
- 개발자도구 **Network → Fetch/XHR** 필터로 API 통신만 표시 → 151마리 확인.

### API 개념
- **API**: 주문을 받는 창구(예: `/api/pokemons`).
- **Request**: "포켓몬 목록 주세요"라고 말하는 행동.
- **Response**: 서버가 JSON으로 돌려주는 것.
- **API ≠ API 키** (다른 개념).

## 4주차 — 데이터베이스 (DB)

### 4-1. 왜 DB가 필요한가

- 새로고침해도 사라지지 않는 **영구 저장**, 다른 유저와 **공유 가능한 저장소**.
- 브라우저는 DB에 직접 접근 권한이 없음 → **서버**를 통해 DB를 읽고 **API**로 브라우저에 전달.
- 외부서버에 키를 두면 항상 켜져 있고 어디서든 접근 가능.

### 4-2. 저장 위치 분류

| 종류 | 위치 | 공유 | 비고 |
|------|------|------|------|
| **localStorage** | 브라우저 | ❌ (내 브라우저만) | 프로토타이핑용. JSON으로 저장 |
| **SQLite** | 내 컴퓨터의 파일(.db) | ❌ | 폴더·txt처럼 파일단위. 옛날 임베디드(아이폰 등)에도 들어감 |
| **MySQL / PostgreSQL** | 외부 DB 서버 | ✅ | 관계형. 24시간 켜진 데이터 창고 |

- localStorage 위치 (Windows 크롬): `C:\Users\[사용자명]\AppData\Local\Google\Chrome\User Data\Default\Local Storage\` — leveldb 또는 SQLite로 저장.
- 외부 DB 서비스: **Supabase**, Neon, AWS — 시크릿키(URL) 필요.

```
MySQL / PostgreSQL = "데이터 창고" (DB)
   ↓
Supabase / Neon / AWS = "24시간 켜진 외부 데이터 창고"
   ↓
server.js = "창고에서 데이터 꺼내 브라우저에 보여주기"
```

### 4-3. 데이터 구조: 관계형(RDB)

- 비관계형(유연한 스키마)은 관계 짜기 어려움. 요즘 표준은 테이블 기반의 **관계형 DB(RDB)**.
- 비유: 노션 테이블의 "릴레이션" 기능. 면접관-면접자 테이블끼리 관계로 묶기.
- **DB 스키마를 짠다 = DB 구조를 짠다.**

### 4-4. Todo 앱을 4가지 방식으로 만들기 (단계적 발전)

> 같은 UI(`index.html`)를 복붙해서 저장소만 갈아끼우는 연습.

#### A. txt + 서버
1. "todo 5개 txt 작성해줘" → DB 생성.
2. `@single-react-dev`로 todo UI(`index.html`).
3. `@single-server-specialist`로 "이 txt를 todo와 연결하는 서버 만들어줘".
   - **API 만들기 = DB에 접근하는 통로 만들기** (읽기/추가/수정).
   - 클라이언트는 하드코딩을 지우고 서버 API에서 받아옴.
4. 쉘에서 `cd 폴더 && node server.js` → `http://localhost:3000`.
5. 웹 ↔ DB 양방향 연동.
- 한계: txt는 **파싱**이 필요해서 서버 부담↑. 정확한 패턴이어야 안정적인 데이터 추출.

#### B. JSON으로 변환
- 컴퓨터가 읽기 쉬운 JSON으로 바꾸면 파싱 코드 거의 없어짐 (`JSON.parse` 한 줄).
- 개발자모드 → Network → Fetch/XHR → Response의 표준 포맷이 JSON.
- 절차: `todos-json/` 폴더 생성 → `index.html` 복붙 → "txt를 json으로 합쳐줘" → "이 폴더에 서버 만들어 연결해줘".
- 결과: server.js의 파싱 로직 거의 없어짐 → 코드 짧고 안정적.

#### C. SQLite로 (속도·분석)
- 더 빠른 속도, **SQL 쿼리로 데이터 분석** 필요할 때.
- 절차: `todos-sqlite/` 폴더 → `index.html` 복붙 → "json DB를 SQLite 파일로 옮겨줘" → `todos.db` 생성.
- VSCode 익스텐션 **SQLite Viewer** 설치 → `.db` 파일을 엑셀표 형태로 확인 가능.
- 서버 코드 작성 → SQL 언어로 데이터를 뽑아오는 구조.
- 패키지 설치 필요(`better-sqlite3` 등) → `package.json` 생성. 외부 패키지를 가져다 쓰는 흔적.

#### D. localStorage 버전 (서버 없이)
- 서버 필요 없는 브라우저 단독 앱.
- 폴더 만들고 `index.html` 복붙 → "로컬스토리지 사용하는 앱으로 바꿔줘".
- 콘솔에서 `localStorage` 입력하면 저장된 todo가 JSON으로 보임.
- **단점**: 내 브라우저에서만 보임, 공유 불가, 다른 브라우저·재설치 시 사라질 수 있음.

### 4-5. 외부 DB 서버 (Supabase PostgreSQL)

#### 가입·프로젝트 만들기
1. supabase.com 회원가입 → New Project (무료 플랜은 프로젝트 2개까지).
2. 프로젝트 이름 + **패스워드는 generate로 자동생성** → 다른 곳에 복사 보관.
3. **Region**: 배포 기본 서버가 US East 1이라 기본은 그쪽. 한국 사용자만 빠른 응답을 원하면 둘 다 서울로 일치시켜도 됨(거리↓ → 속도↑).
4. **Security 영역 체크 해제**(체크 시 Supabase가 백엔드를 별도로 만들어 구조가 복잡해짐).

#### URL 받기 → 연결
5. **Connect 버튼** → ORM **Drizzle** 선택 → 스크롤 하단 **URL 복사**.
6. 커서 메모장에 URL 붙여놓고 `[YOUR-PASSWORD]` 부분을 위에서 만든 패스워드로 교체. (대괄호 포함 통째로 갈아끼우기).
7. Claude로 가서 수정한 URL 붙여넣고 "이 DB에 todo 5개 넣어줘".
   - 클로드가 테이블 만들고 5개 삽입 → Supabase Table Editor에서 확인.
8. 컬럼 부족하면 "content 필드 추가하고 내용 채워줘" → SQL로 채워줌.

#### todos-postgresql 폴더로 앱 구성
9. `todos-postgresql/` 만들고 **API를 쓰는 index.html**(localStorage 버전 X)을 복붙.
10. 그 폴더에 "서버 만들고 api 연동해줘" `@single-server-specialist`.
11. 실행하기. 웹에서 todo 체크 → Supabase 새로고침 → true로 반영. 양방향.
- DB에서 직접 수정/삭제도 웹에 반영되지만 **권장 X**(앱 로직 우회).
- 외부 DB는 **24시간 켜져 있고 URL만 있으면 어디서든 접근**. 다른 컴퓨터/친구/호스팅 어디서든 같은 DB → **반영구 저장**.

- 최근 Claude 플러그인에도 Vercel 등장.

### 5-1. 4주차 복습: 냉장고 재료 + 레시피 앱

#### 5-1-1. Supabase + 백엔드 함정 주의
- "Enable Data API" 체크하면 Supabase가 별도 백엔드 서버를 더 만들어 줌(브라우저용 supabase-js 호환).

- 클로드도 종종 "Supabase JS 서버로 호스팅할까요?"라고 물어봄 → **이건 함정**(아직 서버를 안 만들었으니 추천한 것뿐).
  - "supabase-js 제외해달라" 명령.
- **왜 함정인가**: Supabase는 supabase-js / Auth / Storage 같은 자체 서비스 묶음을 써야 돈을 번다. 우리가 처음부터 그쪽으로 들어가면, 나중에 자체 서버로 떼어내기가 어려워짐(락인). **우리는 Supabase가 제공하는 무료 PostgreSQL DB만 빌려 쓴다.**
- 교훈: AI는 전체 플랜을 모르고 개별 추천을 함. 한 가지 방법을 제대로 알고 있어야 AI 추천을 비판적으로 볼 수 있음.

#### 5-1-2. 흐름 정리

7. Vercel 배포.
8. 중간중간 "변경사항 git에 commit해줘" — 깃 초기화부터 알아서 처리.
9. "레시피 추가 기능 만들어줘".

11. `@vercel-deploy-optimizer`로 Vercel 재배포.

### 5-2. 로그인 / 회원가입 (JWT)

#### JWT(JSON Web Token) 개념
- DB에 유저 정보 저장 → 서버에서 인증 → 인증되면 **토큰(키) 1개**를 브라우저에 발급 → 그 토큰을 헤더에 넣어 다음 요청들 보내면 서버가 인증된 사용자에게만 응답.
- 구글/카카오 로그인도 본질은 같음. 다만 카카오·구글 플랫폼에서 앱을 만들고 추가 인증을 한 번 더 받음.

#### Todo 앱에 인증 붙이기
1. `@react`로 Todo UI.
2. 기존 Supabase URL 그대로 + "테이블 prefix는 `TODO_app`으로 해서 충돌 막고, 데이터 적당히 넣고, DB 구조 짜줘".
   - 1·2 프롬프트 한 번에 줘도 알아들음.
3. `@server-specialist`로 "이 DB 서버 만들고 프론트와 연결해줘".
4. **"JWT 인증으로 로그인/회원가입 (이메일·비밀번호) 추가해줘".**
5. 시드값(seed) — 처음 DB가 비었을 때 씨앗처럼 뿌려두는 초기 계정. Claude가 계정을 만들었다고 답하며 이메일·비번 알려줌.
6. Supabase Table Editor → users 테이블 → 계정 확인. **비번은 그대로가 아닌 서버에서 암호화해 저장** (해시).

#### 디버깅 패턴 (회원가입 에러 났을 때)
1. 개발자도구 → **Console 탭** → 에러 자바스크립트 복붙해서 클로드에 질문.
2. 더 자세히 → **Network 탭** → 빨간 줄 → 에러 코드(예: 500) → **Payload / Headers / Response** 확인:
   - 어떤 페이로드를 줬고
   - 어떤 파라미터가 같이 갔으며
   - 응답이 어떻게 왔는지
3. 그 내용을 클로드에 그대로 붙여넣으면 해결해줌. (특수하거나 학습이 안 된 영역은 여전히 어려움.)

#### 로그인 후 토큰 확인
- 로그인 전: 콘솔에 `localStorage` 입력해도 비어 있음.
- 로그인 후: `localStorage`에 todo앱 키(JWT 토큰)가 들어 있음.
- Network → 요청 헤더(Authorization 등)에서 같은 토큰 확인 가능.
- 서버는 그 토큰을 검증해서 **인증된 사용자에게만 응답**.

### 5-3. 관리자 대시보드

- 사용자가 많아지면 **슈퍼 관리자**가 한눈에 보는 화면이 필요.
- 같은 앱 안에 권한 분리로 만들어도, 별도 앱으로 빼도 됨.
- 분리해도 **같은 DB URL을 공유**하면 데이터는 한 곳에서 관리됨 — 앱이 두 개여도 컨텍스트는 하나.

### 5-4. MCP (Model Context Protocol)

> AI 에이전트가 우리 대신 컴퓨터·앱·웹을 쓰는 약속(프로토콜). 노션, 피그마, 워크플로우, 노트앱, 브라우저(Playwright/Chrome DevTools), 지메일/캘린더/드라이브 등 다양.

#### 5-4-1. 노션 MCP
1. 클로드 코드에 `/mcp`.
2. "notion mcp 설치해줘" → 인증 안 돼 있으면 경고 → 인증 클릭 → 외부 브라우저에서 노션 인증 → 게스트로 초대된 워크스페이스 많을 때는 원하는 워크스페이스 선택 → 인증 완료.
3. 다시 `/mcp` → 노션 연결 확인.
4. 노션에서 새 페이지 → 우상단 Copy Link (또는 브라우저 URL).
5. 클로드에 노션 URL 붙여넣고 "이 페이지 확인 가능?" → 위치·내용 응답.
6. "이 노션 페이지에 재밌는 내용 넣어줘" → 페이지 자동 작성.
- 응용: 노션도 항상 켜진 서버 → 공동작업 컨텍스트로 좋다. md를 만들어두면 같은 포맷으로 노션에 업로드 가능.

#### 5-4-2. Adobe MCP, 기타
- 구글에 "어도비 mcp" 검색하면 나옴. After Effects / Premiere Pro / Photoshop / Illustrator 등을 클로드가 조작 가능하게 만든 것.
- 프리미어 프로 MCP도 별도로 있음.

#### 5-4-3. Playwright / Chrome DevTools MCP
- 둘 다 **브라우저 컨트롤** 도구.
- 원래 사람이 하던 로그인/UI 회귀 테스트 → Playwright로 자동화 → 그 자동화를 AI에게 맡김. **AI가 브라우저를 가장 쉽게 다루는 방법**이 Playwright.
- Chrome DevTools MCP는 구글이 만든 후발 주자. 콘솔 내용 디테일 파악에 강함.
- 사용 흐름:
  1. "playwright, chrome devtools mcp 설치해줘".
  2. "playwright로 쿠팡 페이지 열어줘" — 쿠팡이 막혀 있으면 네이버.
  3. **"네이버에서 2026년 AI 트렌드 찾아 md 파일로 정리해줘"** — "어디서"를 명시해야 다른 도구로 안 새 나감.
  4. "Reddit 방문해서 최신 이미지 생성 post 찾아 md로 정리해줘" (로그인은 미리 해둠).
  - md로 만들어두면 노션 MCP로 같은 내용을 노션에 업로드 가능 — 공유 간편.
- **앱 자동 테스트로의 확장**: 우리 앱이 복잡해지면 클로드가 직접 Playwright/DevTools로 테스트 → 에러 발견 → 수정. "만들고 나서 테스트까지 해줘 + 스크린샷 저장해줘".

### 5-5. 리모트 컨트롤 (`/remote-control`)

- **항상 컨텍스트를 읽고 있는 AI 에이전트**가 필요해서 OpenCloud 같은 서비스가 등장. 셋업이 복잡(컴퓨터 셋업 + 설치).
- 가장 쉬운 대안 = 클로드 코드 내장의 **`/remote-control`**.
- 컴퓨터 켜두고 클로드 코드 실행 중 `/remote-control` 입력 → 우측 하단 **Remote Control Active**.
- 코드 상단에 두 개의 커넥션이 보임 → 첫 번째 선택 시 **핸드폰 클로드 코드 앱**에서도 같은 창이 열림.
- 효과: 이동 중에도 핸드폰으로 명령 가능. 컴퓨터의 파일·코드를 클로드가 계속 읽고 있음.
- 클로드 코드 채널로 **텔레그램** 등 다른 메신저에 연결도 가능.

### 5-6. DB + AI 에이전트 패턴

- AI 에이전트한테는 **DB도 노션 접근만큼 쉽다**.
- 예: 냉장고 재료/레시피를 DB에 쌓아두고, 클로드 코드 또는 리모트 컨트롤에서 "새로운 레시피 만들어 추가해줘" → DB에 새 레시피 인서트.
- **에이전트 vs 애플리케이션**
  - 에이전트 — AI(클로드 코드 등)에게 직접 질문해서 데이터 사용.
  - 앱 — AI 없이 인터넷만 있으면 접속해서 데이터 보는 일반 웹앱.
  - 둘이 같은 DB(=같은 컨텍스트)를 공유하면 좋은 데이터 소스가 됨.
- **컨텍스트 3가지**: md(로컬), 노션(공동), DB(영구·공유). 셋 다 꾸준히 유지·업데이트해야 AI 답변 품질이 올라감.

## 자주 헷갈리는 포인트 (1~5주차 통합)

- **에이전트 인식 안 됨** → Claude Code를 껐다 켜야 함.
- **서버 실행은 쉘에서** (`node server.js` / `npm start`), Claude가 아니라 내가.
- **`npm start` ≈ `node server.js`** — `package.json`의 `"scripts": { "start": "node server.js" }` 정의 때문.
- **`npm install` 의미** — 외부 패키지(express, pg 등) 설치. 서버 폴더 옮기면 다시 해야 함.
- **index.html 더블클릭 = `file://`** → 서버 API 안 됨. `http://localhost:포트`로 열기.
- **CORS 에러** → 같은 서버에서 열었는지 확인.
- **콘솔 에러 → 그대로 클로드에 붙여넣기**. 더 깊이는 Network → 빨간 줄 → Status / Payload / Response.
- **하드코딩 데이터** → 프로토타이핑은 OK, 실서비스는 외부 API/DB로 전환.
- **시크릿키·DB URL** → 반드시 **서버 + .env**. 깃 push 전 `.env`가 `.gitignore`에 있는지.
- **Supabase JS 백엔드 추천 == 함정** → 우리는 PostgreSQL DB만 빌려 쓴다.
- **스키마 짤 때 데모 데이터 같이 요청** → 구조 이해 빨라짐.
- **Region** — 클라우드 서버와 DB 서버 위치를 일치시키면 빠름. Vercel 기본은 US East 1.
- **md 컨텍스트는 가끔 누락** — 자료 많으면 CSV 같은 표 포맷이 안전.
- **에이전트 vs 스킬** — 에이전트는 메모리 있음, 스킬은 메모리 없음(매번 컨텍스트 던져야 함).
- **Opus vs Sonnet** — Opus는 토큰 10배. 복잡한 작업만 Opus.
- **토큰 절약** — 정확한 경로 지정, 참고 파일만 명시.
