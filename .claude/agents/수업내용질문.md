## 1주차 — Claude Code & Git

### 1-1. Claude Code 환경 세팅

- **커서(Cursor) / Claude Code / Git 설치 여부 확인**을 Claude에게 먼저 물어본다.
- `ctrl+shift+p` → **open user setting (JSON)** 검색 후 아래 내용을 넣으면 md 파일이 미리보기 스타일로 보임.
  ```json
  {
      "workbench.editorAssociations": {
          "*.md": "vscode.markdown.preview.editor"
      }
  }
  ```
- **모델 설정**: 에이전트 작업 시 화면에서 모델을 선택 가능. **Opus는 Sonnet보다 토큰을 약 10배 더 씀** → 가벼운 작업은 Sonnet.
- **프롬프트 팁**
  - 딱 이 파일만 참고해서 쓰라고 하면 **토큰 절약**.
  - 경로(path)를 정확히 알려주면, Claude가 다른 곳을 뒤지지 않아 토큰 절약.

### 1-2. 에이전트(Agent)

- **에이전트 만들기**: 새 Claude 창에서 `/agents` 입력 → 폴더 설정 선택.
- **Generate with Claude (추천)** vs **Manual configuration**
  | 항목 | Generate with Claude | Manual configuration |
  |------|----------------------|----------------------|
  | 방법 | AI 자동 생성 (설명 입력) | 직접 JSON/YAML 편집 |
  | 난이도 | 쉽고 초보자용 | 전문가용 |
  | 유연성 | 기본 자동화 | 완전 커스터마이징 |
- **도구 그룹 설정 (All tools / Read-only / Edit / Execution / MCP / Other)**: 기본은 전체 선택(All tools). 보안 필요 시 Read-only만.
- **메모리 스코프**
  - `Project scope` (`.claude/agent-memory/`) ← 추천, 프로젝트 전용.
  - `User scope` (`~/.claude/agent-memory/`) 모든 프로젝트 공유.
  - `Local scope` (`.claude/agent-memory-local/`) Git 무시, 민감 데이터.
  - `None` 매번 초기화.
- **프로젝트 vs 퍼스널 에이전트**: 슬래쉬 에이전트 저장 시 "프로젝트(.claude/agents/)"는 프로젝트 전용, "퍼스널(~/.claude/agents/)"은 전역.
- **md 파일은 `.claude/agents/` 아래 있어야** Claude가 에이전트로 인식함. 새 에이전트를 추가하면 **반드시 Claude Code를 껐다(`Ctrl+C`) 다시 켜야** 인식됨.
- 에이전트 불러오기: `@` 입력 후 `.claude/agents/…` 경로 선택 → 그 에이전트로 명령.

### 1-3. 첫 에이전트 만든 흐름 (레시피 에이전트 + K-드라마 에이전트)

1. `recipe-agent.md` 생성 → 껐다 켜기 → `/agents`로 확인.
2. 채팅창에서 `@recipe-agent` 부르고 "굴소스 볶음밥 레시피 만들어줘" → 결과 생성.
3. 이미지가 안 만들어지는 경우 → **나노바나나**로 만들어달라고 함 (API 키 필요).
4. `K-drama expert.md` 에이전트 동일 방식으로 생성.
5. `.claude` 아래 "다이어리" 폴더를 만들고 오늘 날짜로 md 다이어리 작성.
6. 채팅창에서 `@K-drama-expert` + 다이어리 md 경로 붙여넣고 "막장드라마로 써줘" → md 저장.

### 1-4. 메모리 & 뉴스 수집 에이전트

- `news-collector.md` 예시로 만들어 뉴스 자동 생성.
- **파일 생성/저장 절차**: 에이전트 폴더 우클릭 → New → `이름.md` → 오른쪽 창에 내용 붙여넣고 **꼭 저장**.

### 1-5. Git & GitHub

- **Git**: 내 컴퓨터에서만 쓰는 타임라인(세이브포인트). **인터넷 필요 없음.**
- **GitHub**: Git 커밋을 **인터넷에 올려 백업/공유**. Git과는 다름.
- **초기화(initialize)**: 이 폴더를 git으로 관리할거다 선언. Claude에 "git 초기화해줘"라고 명령해도 됨.
- **현재상태 저장** → Claude에 "지금 변경사항 commit 해줘"라고 명령.
- VSCode 왼쪽 패널 git 영역에서 **연결 아이콘 눌러 초기화** → 왼쪽 하단에 `Initial commit` 생성 → 파일들이 하나의 커밋으로 저장된 상태.
- **이전 상태로 되돌리기**
  - 깃폴더에서 `Initial commit` 우클릭 → **checkout (detached)** → 이전 상태.
  - 혹은 Claude에게 "첫번째 커밋으로 돌아가줘" 프롬프트.
  - `Discard all change` 누르면 바뀐 파일 원복.
  - `/rewind` 슬래쉬 커맨드로 이전 버전으로 복구.
- **깃 저장 위치**: 프로젝트 루트의 `.git/` 폴더 안. `objects/`(실제 커밋·파일), `refs/`(브랜치/태그), `HEAD`, `config`, `logs/`.
- **GitHub에 푸시**
  - Claude에 "GitHub에 푸시해줘"라고 하면 계정·로그인·CLI 상태를 먼저 확인시킴.
  - **CLI 로그인 안 될 때**: 별도 cmd창 열고 `gh auth login` → yes → `Login with a web browser` 선택 → 코드 복사해서 GitHub 홈페이지에 붙여넣고 Continue.
  - **리포지토리(저장소) = 코드 저장소**. 공개(public)로 만들고 push.
- 파일 지우고 commit하면 "md 파일을 지웠다"로 changes에 표시됨. 다시 커밋 가능.

## 2주차 — HTML / CSS / JS + React 에이전트 (single-react-dev)

### 2-1. `single-react-dev` 에이전트 설치

- `single-react-dev.md` 파일을 `.claude/agents/` 폴더에 넣어준다.
- Claude 껐다 켜서 `@single-react-dev` 입력으로 에이전트 호출.

### 2-2. 폴더/파일 만드는 흐름 (공통 패턴)

1. `week-2` 아래 새 폴더 생성 (예: "나이계산기").
2. 그 폴더에 `index.html` 파일 생성. **확장자가 중요**.
3. 파일 경로를 **우클릭 → Copy Path** 로 복사.
4. 채팅창에 `@single-react-dev` 입력 + 폴더 경로 붙여넣기 + 명령.
   예) "이 폴더에 나이계산기 만들어줘. CSS도 넣어줘."
5. 만들어지면 왼쪽 패널에서 우클릭 → **Reveal in File Explorer** → 폴더에서 크롬으로 열기.

### 2-3. 프롬프트 입력 순서 (중요 패턴)

```
1. @"single-react-dev (agent)"
   └ my-pokemon-docs 여기에 간단하게 포켓몬
     검색할 수 있는 UI 그려줘
     포켓몬 5마리 너가 넣어줘

2. @"single-server-specialist (agent)"
   └ my-pokemon-docs 여기에
     포켓몬 데이터를 api로 뿌려주는 서버
     만들어줘

3. index.html 에서 이 서버 api를 사용해줘
   (하드코딩된 포켓몬 말고)
```
→ **UI → 서버 → 연결** 순서로 프롬프트 하는 것이 기본 패턴.

### 2-4. 개발자 도구(F12) 사용법

- 크롬 우상단 → Developer Tools. 또는 `F12`.
- **Console(콘솔)**: 에러가 뭐에서 났는지 보여줌. 에러 뜨면 **그대로 복사해서 Claude에 붙여넣기**.
- **Network(네트워크)**: 서버와의 통신을 봄. URL이 `file://`인지 `http(s)://`인지 확인 가능.
  - 없는 서버의 index.html을 직접 열면 `file://` (인터넷 없이 파일만 읽은 것).
  - 로컬호스트(서버)로 열면 `http://`로 바뀜.
- **스킬 써줘**: 클로드에 "스킬 써서 넣어줘" 같이 특정 스킬 호출도 가능.

## 3주차 — 서버 / Node.js / Express / API

### 3-1. 왜 서버가 필요한가

- 로그인, 회원가입, **데이터베이스**, **결제**.
- **AI 서비스** 만들 때: **API 키를 숨겨야** 하므로 서버단이 필요.
- **index.html만 만들면 인터넷이 필요 없다** — 그냥 크롬에서 파일을 연 것뿐.
- 서버에 index.html을 올리고 도메인을 붙이면 다른 사람이 접속 가능 = **static 파일 서빙**.
- 서버의 역할 2가지
  1. **static files 서빙** (고정 파일: html/css/img/font 등)
  2. **API 서빙** (데이터/기능)

### 3-2. Node.js / Express / npm

- 서버는 **JavaScript(Node.js)** 로 만든다. → 프론트도 JS, 서버도 JS. 요즘 대세.
- "간단한 node 서버 만들어줘" = **Node.js로 서버 구성해달라는 뜻**.
- **npm = Node Package Manager**.
- **package.json**: 외부 사람들의 오픈소스 패키지를 우리가 설치해서 쓸 때의 **명세서**.
  - 예) 비밀번호 암호화 알고리즘을 직접 짜지 않고, 암호화 패키지를 가져다 씀.
- **express**: Node.js 표준처럼 쓰이는 서버 프레임워크.
  - 기본 Node.js http보다 코드가 짧고, 정적파일 서빙(폴더명만), 라우트 분리가 깔끔해짐.
  - 에이전트가 express를 쓰면 `package.json`이 생기고, **외부 패키지이므로 설치 필요** (`npm install`).
  - Claude에게 "node.js 서버를 express로 바꾸고 변경사항 md로 정리해줘" 요청 → 변경사항 md 확인 가능.

### 3-3. `single-server-specialist` 에이전트 흐름

1. `.claude/agents/` 안에 `single-server-specialist.md` 넣고 Claude 재시작.
2. 프롬프트 예: **"간단한 node 서버 만들어줘. static file 서빙 예시와 간단한 hello API 예시 만들어줘."**
3. 결과: `server.js` + `public/` 폴더 안에 `index.html`.
   - **public 폴더가 생기는 이유**: 공개되는 이미지/폰트 등을 넣어두고 `server.js`에서 public 폴더의 파일을 static으로 서빙.
   - `public` 바깥 경로를 해커가 요청할 수 있으니 **경로 검증 보안 코드**가 들어 있음.
4. 서버 실행은 Claude가 아니라 **쉘에서 직접**:
   - 쉘에서 `cd`로 서버 폴더 이동 → `ls -la`로 파일 확인 → `node server.js`.
   - 주소(`http://localhost:3000` 등)가 뜨면 브라우저로 접속.

### 3-4. localhost / IP / 같은 와이파이 접근

- **localhost = 127.0.0.1** = "내 컴퓨터" (집주소 축약 버전).
- 자기 컴퓨터에 띄운 서버에 가장 빠르게 접속하는 방법: `http://localhost`.
- 같은 와이파이의 다른 기기(폰 등)에서 접속하려면 **내 컴퓨터의 내부 IP** 사용.
  - 와이파이 잡으면 IP 2개 할당: `192.x.x.x` = 내부 IP / `137/17/67` = 외부 IP.
  - `node server.js` 실행 시 뜨는 IP는 내 컴퓨터에 할당된 것.
  - Claude에 "같은 와이파이 사람들이 내 서버로 들어올 수 있게 해줘" 라고 부탁하면 됨.
- **포트**: localhost는 하나지만 포트는 여러 개 (3000, 4000 …). 여러 Node 서버를 띄우려면 포트 번호만 다르게.

### 3-5. GET vs POST

```
GET : "이미 준비된 파일 줘!"   → 즉시 응답   (static 파일 / 열린 API)
POST: "새로 계산해서 만들어줘!" → 처리시간 필요 (결제/가입 등)

예시
GET  /users   → DB에서 0.1초만에 조회
POST /order   → 결제처리 + 재고체크 + 이메일발송 (2~3초)

인증이 필요한 경우
❌ GET  /login?email=***&pw=***   ← 비번 URL에 노출!
✅ POST /login                     ← 비번 body에 숨김
```

### 3-6. `http.createServer` 내부 흐름 (기본 Node.js 서버)

- HTML 응답은 `readFile`로 디렉토리 파일을 읽고, 에러가 없으면 `res`로 해당 파일을 응답.
- 응답(response)에는 html 내용이 들어있는 것을 개발자 도구 Network 탭에서 확인 가능.

## 3주차 프로젝트 ① — 포켓몬 도감 (index.html만 → 서버화)

**목적**: 하드코딩된 포켓몬 데이터를 **서버 API로 옮기고**, **외부 PokeAPI**까지 사용.

### 흐름

1. **프론트 만들기**: `@single-react-dev`로 "포켓몬 5마리 도감 UI" 생성.
   - 이 시점엔 서버 없음. 데이터는 `index.html`에 하드코딩. 개발자도구 네트워크에 URL이 `file`로 뜸.
2. **서버 만들기**: `@single-server-specialist`로 "이 폴더에 포켓몬 데이터를 API로 뿌려주는 서버 만들어줘".
   - `server.js`로 포켓몬 데이터 이동. `/api/pokemons` 주소로만 노출됨.
   - → **API 요청을 하지 않으면 데이터가 보이지 않음** (보통 결제/주문 데이터를 서버에 숨기는 것과 같은 원리).
3. **프론트를 서버 API와 연결**: "index.html에서 이 서버 api를 사용해줘. 하드코딩된 포켓몬 말고".
4. **npm 설치**: 새 서버 폴더에서 `npm install` 혹은 Claude에게 설치해달라고 명령.
5. **서버 실행**: 쉘에서 `node server.js` → 주소 뜸.
6. **확인**: 로컬호스트(`http://localhost:3000`)로 열면 정상, **파일로 직접(`index.html` 더블클릭) 열면 데이터 안 보임**.

### CORS 에러

- `file://`로 index.html을 열면 **자기 서버를 인식 못 해 CORS 에러**로 데이터 반환 X. Node.js 기본 보안.
  - 열 수도, 닫을 수도 있음.
- **PokeAPI**는 CORS 정책이 열려 있어서 어떤 방식으로 열어도 데이터 받아올 수 있음.

### PokeAPI로 확장

- 하드코딩 한계: **5마리 → 100마리/1000마리 되면 직접 넣기 힘들고, 데이터 정확성 보장 어려움, 신규 포켓몬 수동 반영 필요**.
- **PokeAPI** (포켓몬 데이터 자동 업데이트, 대량 데이터) 사용.
- 프롬프트: "PokeAPI 이용해서 포켓몬 데이터 검색과 연결해달라".
- 결과: 하드코딩 데이터 제거 + 백엔드가 외부 API 호출.
- **개발자도구 Network → Fetch/XHR** 필터로 API 통신만 볼 수 있음 → 151마리 포켓몬 데이터가 클라이언트에 저장된 걸 확인.

### API 개념 정리

- **API**: 주문을 넣는 창구 (예: `/api/pokemons`) — 주문을 **받는 통로**.
- **요청(Request)**: "포켓몬 목록 주세요" 라고 말하는 행동.
- **응답(Response)**: 서버가 JSON 데이터로 돌려주는 것.
- **API ≠ API 키** (다른 개념).

## 3주차 프로젝트 ③ — AI 친구 채팅 (OpenAI API + 시크릿키 관리)

### 흐름

1. `@single-react-dev`로 채팅 UI를 그려달라.
   - 이 시점엔 html 열면 **고정된(하드코딩된) 답변** 몇 개만 보임.
2. `@single-server-specialist`로 **채팅에 AI 응답을 만들어주는 API 만들어줘** 프롬프트.
   - OpenAI를 쓰라 지시 + **키 입력**.
   - HTML의 하드코딩 지우고 서버 API를 쓰도록 리팩터.
3. 서버 실행 요청 → 로컬호스트 열면, 채팅에서 `/chat` API를 직접 호출하고 있음.
4. 하드코딩 답변이 사라지고 **서버에서 받아옴**.

### 서버와 OpenAI의 관계

- 내 서버가 OpenAI 입장에서는 **클라이언트** 역할.
- 브라우저 → (나의) 서버 → OpenAI → 서버 → 브라우저, 응답을 두 번 감싸는 구조.
- **시크릿키를 숨기기 위한 서버**. 브라우저는 서버 코드를 읽을 수 없기 때문.

### API 키: 퍼블릭 키 vs 시크릿 키

- 시크릿키는 **브라우저(클라이언트)에 노출되면 안 됨**. `index.html`에 넣으면 누구나 읽고 악용 가능.
- **.env 파일 (environment 환경변수)**
  - 소스코드에서 키를 분리.
  - 자동 생성이 안 됐으면 Claude에 "env로 키 분리해줘" 프롬프트.
  - **굳이 .env로 분리하는 이유**: 서버 코드는 브라우저에서 안 읽히지만, **GitHub에 push하면 공개됨**. 깃허브에 올라가는 것을 막기 위해서 분리.
- **.env.example**: 가짜 키값을 넣어둔 예시 파일. 실제 키 없이 형식만 공유.

## 질문 시 자주 헷갈리는 포인트 (나중에 다시 찾아볼 용도)

- **에이전트 인식 안 됨** → Claude Code를 껐다 켜야 함 (`.claude/agents/` 새 파일 추가 후 필수).
- **서버 실행은 쉘에서** (`node server.js`), Claude가 아니라 내가.
- **index.html 더블클릭으로 열면 서버 API 안 됨** → `http://localhost:포트` 로 열어야 함.
- **CORS 에러** → 같은 서버에서 열었는지 확인.
- **콘솔 에러 뜨면** → 그대로 Claude에 붙여넣고 해결 요청.
- **하드코딩 데이터** → 프로토타이핑엔 유용하나, 데이터 검증/관리 어려움. 외부 API로 전환.
- **시크릿키** → 반드시 **서버 + .env**. 깃허브 푸시 전 `.env`가 `.gitignore`에 있는지 확인.
- **토큰 절약** → 정확한 파일/경로 지정, 참고 파일만 지정.
- **Opus vs Sonnet** → Opus는 토큰 10배. 복잡한 작업만 Opus.
