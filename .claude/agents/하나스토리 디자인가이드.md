# 하나스토리 디자인 가이드 (상세판)

> `하나스토리 홈페이지 구축가이드.md`가 구조/인증/배포 같은 **기술 아키텍처**를 다룬다면, 이 문서는 **비주얼 톤앤매너**를 다룬다. 실제 `style.css`(총 1264줄) 전체를 근거로 모든 컴포넌트의 실제 수치를 담았고, 그중 성찬님이 직접 프롬프트로 조정한 부분은 인용과 함께 "왜 이렇게 바뀌었는지"를 남겼다. 새 화면을 만들거나 기존 화면을 손댈 때 "여기 색은 뭘 써야 하지?", "간격은 몇 px?", "이 컴포넌트 패턴 어디 또 있지?" 같은 질문에 코드 없이 이 문서만 보고 답할 수 있는 걸 목표로 함.

## 1. 색상 팔레트 (`style.css` `:root`, 47~62행)

```css
--navy:        #1a2b45;   /* 메인 컬러 */
--navy-light:  #253d5e;   /* navy hover */
--green:       #1a2b45;   /* navy와 동일값 — 포인트 언더라인/체크 아이콘 등에 의미상 구분해 씀 */
--green-dark:  #0f1e33;
--green-light: #253d5e;
--text:        #444;      /* 본문 */
--text-dark:   #222;      /* 제목 */
--text-light:  #777;      /* 보조 설명 */
--bg-light:    #f9f9f9;   /* 섹션 배경(옅은 회색) */
--bg-gray:     #f4f4f4;   /* 표 헤더 배경 등 */
--border:      #ddd;      /* 기본 구분선 */
--border-dark: #999;      /* 진한 구분선 (표 하단 등) */
```

- **`--green`이 `--navy`와 같은 값(`#1a2b45`)이라는 게 중요한 함정**: 변수명은 "그린"이지만 실제로는 네이비다. 새로 CSS를 추가할 때 "그린이니까 초록"이라고 착각하지 말 것 — 명시적으로 색을 바꾸고 싶으면 `--green` 재정의가 아니라 새 변수를 만들어야 함.
- **진짜 포인트 컬러(변수화 안 됨, 하드코딩 반복 사용): 틸/청록 `#1e5e68`** (hover 시 `#164a52`). 아래 위치에서 반복 등장:
  - 회사연혁 타임라인 체크마크(`.tl-check`)와 연도 언더라인(`.tl-year-line`)
  - 히어로 CTA 버튼(`.hero-cta`) 배경
  - 홈 제품 프리뷰 카드의 "자세히 보기" 아웃라인 버튼(`.pp-link`)
  - 가로 스크롤 진행바(`.pd-scrollbar-thumb`)
  - **원칙**: 네이비는 "구조"(헤더, 표, 카드 보더), 틸은 "행동을 유도하는 지점"(CTA, 체크 완료 표시, 스크롤 진행)에만 쓴다.
- 배지류(`.grade-1`, `.pspec-badge`, `.tag-ks` 등)는 전부 동일한 연한 배경 `#eeeff4` + 텍스트 `#1a2b45` 조합 — 배지 색을 종류별로 다르게 주지 않고 하나로 통일해서 정보 위계를 텍스트 내용으로만 구분(색으로 구분하지 않음).

## 3. 레이아웃 & 간격 시스템

- **컨테이너**: `.container { max-width: 1200px; margin: 0 auto; padding: 0 20px; }` — 반응형에서 1024px 이하일 때 좌우 패딩만 16px로 축소, 최대폭 자체는 안 건드림(뷰포트가 1200px 밑이면 자연히 꽉 참).
- **섹션 세로 여백**: `.section { padding: 96px 0 108px; }` — 위아래 비대칭(아래가 12px 더 김). 768px 이하에서는 `48px 0 56px`로 축소(비율 유지).
- **섹션 배경 변형**: `.section-gray`(옅은 회색 `--bg-light`), `.section-dark`(짙은 네이비 `--green-dark`) — 톤 전환용으로 섹션 단위로만 배경을 바꾸고, 섹션 내부에서 색이 또 바뀌는 경우는 없음.
- **그리드 gap 관례**:
  - 카드형 3열 그리드(`.cert-grid`, `.product-grid`, `.prod-preview`): `gap: 20px`
  - 2컬럼 콘텐츠 대비(이미지+텍스트류 `.intro-grid`, `.contact-grid`): `gap: 60px` (여유 있게)
  - 사진 갤러리(`.home-gal-grid`, `.gallery-grid`): `gap: 6px` (사진끼리는 촘촘하게 붙임 — 위 두 경우와 대비되는 유일한 "타이트 gap" 컨벤션)
- **섹션 제목 패턴(`.sec-head`)**: 라벨 + 타이틀을 세로로 쌓고, 타이틀 우측으로 남는 공간을 얇은 회색 선(`::after`, `calc(100% - 220px)`)으로 채워서 "제목 블록(220px) + 나머지는 선"이라는 가로 리듬을 만듦. 이 220px은 `.sec-title`의 `min-width`와 정확히 일치시켜야 선이 제목 바로 옆에서 시작함.

## 4. 컴포넌트 상세

### 4-1. 헤더 / GNB
- 고정(`position: fixed`) 흰색 반투명(`rgba(255,255,255,0.97)`) 헤더, 높이 100px.
- 로고는 절대좌표로 좌측 고정(`left: 20px`), GNB는 우측에서 170px 띄운 위치부터 시작(우측 언어토글 공간 확보).
- GNB 1뎁스: `padding: 0 26px`, `font-size: 18px`, hover/active 시 네이비 배경 풀필(`background-color: rgba(26,43,69,1.0)`) + 흰 글씨로 반전.
- GNB 드롭다운(2뎁스): 반투명 회색(`rgba(240,240,240,0.97)`), 상단에 3px 네이비 보더로 "메뉴에서 이어진다"는 느낌. hover 시 `rgba(26,43,69,0.14)` 배경.
- 언어 토글(`.lang-wrap`): 캡슐형 배경(`border-radius: 20px`) 안에 KR/EN 버튼 2개, 활성 버튼만 네이비 필. 다크모드 토글과 동일한 UX 패턴(둘 중 하나 선택형 필 스위치).
- 모바일(1024px 이하): GNB가 드롭다운 아코디언 없이 **전체를 세로 스택**으로 펼침(`nav.gnb.open { display: flex; flex-direction: column }`), 2뎁스 드롭다운은 아예 숨김(`display: none !important`) — 즉 모바일에서는 1뎁스 링크만 보이고 하위 카테고리는 각 페이지 진입 후 `.sub-nav-bar`에서 선택하는 구조.

### 4-2. 서브페이지 배너 (`.page-banner`)
- 높이 380px(가운데 정렬형 `.page-banner--center`는 420px), 배경 이미지 + 대각선 그라디언트 오버레이(`135deg`, 보라~네이비~그린 계열 3색 블렌드, 투명도 0.7~0.82).
- 타이틀은 좌하단(또는 center 변형은 정중앙) 정렬, `bottom-up fade` 애니메이션(`bannerFadeUp`, `cubic-bezier(0.22,1,0.36,1)`) — 타이틀이 0.1s 딜레이로, 서브텍스트가 0.28s 딜레이로 순차 등장.
- 타이틀 왼쪽에 세로 바(`::before`, 1.5px 두께, 반투명 흰색)를 장식으로 붙임 — 텍스트 앞에 "구분자"를 두는 시각적 습관 (연혁 페이지 등 다른 곳에서도 반복됨).

### 4-3. 서브탭 두 종류 — 헷갈리지 말 것
사이트에 탭처럼 보이는 게 2종류 있고 용도가 다름:
1. **`.sub-tab-row`**: 배너 하단에 반투명하게 겹쳐지는 탭(taesungenc 원본 스타일) — 현재 실사용 페이지는 적고 대부분 `.sub-nav-bar`로 대체됨.
2. **`.sub-nav-bar`**: 배너 아래 **흰 배경 위에 올라오는** 탭 — 실제로 사이트 전역에서 쓰는 건 이쪽. `padding: 16px 26px`, 비활성 회색(`#666`) → hover 시 `#f4f5f7` 배경, **active 상태는 네이비 풀필(`background: var(--navy); color:#fff; font-weight:700`)**. 등장 시 5개까지 순차 딜레이 애니메이션(`navTabIn`, 0.05s 간격).

### 4-4. 표 4종 — 용도별로 분리되어 있음 (섞어 쓰지 말 것)
| 클래스 | 용도 | 상단 보더 | 헤더 배경 | 폰트 크기 |
|---|---|---|---|---|
| `.board-table` | 일반 게시판형(자료 목록 등) | `2px solid #222` | `--bg-gray` | 15px |
| `.info-table` | 키-값 정보(회사개요, 오시는 길) | `2px solid var(--navy)` | `--bg-gray`, `width:160px` 고정 | 15px |
| `.proj-board` | 주요납품실적 표 | `2px solid #222` | `--bg-gray` | 15px(모바일 14px) |
| `.spec-table` | 제품 규격 상세표 | `2px solid var(--navy)` | `--bg-gray` | 14px |

공통 규칙: **표 안쪽 세로 보더는 옅은 회색(`#ddd`), 바깥 테두리(상/하)만 진하게** — 표 왼쪽·오른쪽 끝 셀은 좌우 보더를 제거(`border-left:0`/`border-right:0`)해서 표가 컨테이너 안에서 "떠 보이지" 않게 함. `tbody tr:hover td { background:#fafafa }`로 행 hover 피드백 통일.

### 4-5. 카드 컴포넌트 3종
1. **`.cert-card`** (인증 카드): 상단 3px 네이비 보더 + 회색 이미지 박스(`object-fit: contain`, 로고/문서 스캔본처럼 여백 있는 이미지에 적합) + hover 시 `translateY(-3px)` + 그림자.
2. **`.product-card`** (제품 목록 카드): 얇은 회색 보더(`#e2e2ee`), 이미지는 `object-fit: cover`(사진처럼 꽉 채우는 이미지에 적합) + hover 시 `scale(1.04)` + `z-index:2`로 확대되며 다른 카드 위로 떠오름.
3. **`.pp-card`** (홈 "주요제품" 프리뷰 카드): `product-card`와 거의 동일하지만 상단 보더가 3px로 더 두껍고, hover 확대율도 더 큼(`scale(1.06)`) — **홈 화면의 카드일수록 hover 반응을 크게 줘서 "여기부터 둘러보라"는 유인을 강하게 준다**는 암묵 규칙.

카드 이미지 처리 원칙(4-5 공통): 로고/문서/인증서처럼 **여백이 있어야 하는 이미지 → `contain`**, 실물 사진처럼 **프레임을 꽉 채워야 하는 이미지 → `cover`**. 이 사이트에서 `cover`를 쓸 땐 반드시 프레임의 `aspect-ratio`를 실제 이미지 비율에 맞춰야 한다는 원칙은 §5-2 참고.

### 4-6. 갤러리 — 그리드 2종
1. **`.home-gal-grid`** (홈 프리뷰): 3열 고정 그리드, `aspect-ratio: 4/3` 고정 크롭, 호버 시 어두운 오버레이(`rgba(8,16,30,0.72)`) 위에 흰 텍스트가 중앙 정렬로 페이드인 + `scale(0.94→1)`.
2. **`.gallery-grid`** (전체 갤러리 페이지): `columns: 3` **CSS 멀티컬럼(masonry 흉내)** — 그리드가 아니라 컬럼이라 이미지 원본 비율 그대로 쌓이고 `break-inside: avoid`로 카드가 컬럼 경계에서 잘리지 않게 함. 하단 좌측 정렬 캡션(gradient 오버레이 + 텍스트, hover 시 노출).

두 그리드는 완전히 다른 CSS 기법(고정 그리드 vs 멀티컬럼)을 쓰고 있으니, "갤러리 하나 더 만들어줘" 요청이 오면 **어느 쪽 패턴을 원하는지 먼저 확인** — 프리뷰용 정갈한 정사각 그리드인지, 실적 갤러리용 자유로운 세로 masonry인지.

### 4-7. 히어로 (`index.html` 전용)
- 풀스크린(`100vh`) 배경 슬라이드쇼 — `.hero-slide`가 여러 장 `position:absolute`로 겹쳐있고 `opacity` 전환(1.8s)만으로 크로스페이드. `.hero-dots`로 수동 슬라이드 이동 가능.
- 텍스트 3단 순차 등장(`heroFadeUp`): 타이틀 0.15s → 서브 0.4s → CTA 0.65s 딜레이 — 위→아래 요소가 아래로 갈수록 늦게 뜸.
- 타이틀 텍스트 그림자(`text-shadow`)를 이중으로 줌(넓게 퍼지는 그림자 + 촘촘한 그림자) — 배경 사진이 밝아도 글씨가 항상 읽히게 하는 안전장치.
- 스크롤 유도(`.hero-scroll`)는 텍스트 없이 세로 바 하나가 `scrollPulse` 애니메이션(2s, opacity 0.3↔1)으로 깜빡임 — "아래로 스크롤하세요" 문구를 아예 안 쓰고 시각 신호만으로 유도.

### 4-8. 버튼 3종
```css
.btn         { background: var(--navy); color:#fff; padding: 14px 36px; }         /* 기본형 — 채움 */
.btn-green   { background: var(--green); }                                        /* navy와 동일색, 의미 구분용 */
.btn-outline { background: transparent; color: var(--navy); border:1px solid var(--navy); } /* 아웃라인 */
```
+ `.pp-link`(홈 제품 카드 "자세히 보기")는 위 3종과 별개로 **틸 컬러 아웃라인**(`border:2px solid #1e5e68`) — 유일하게 navy 계열이 아닌 버튼. **원칙**: 페이지 레벨의 주요 CTA는 navy 계열, 카드 내부의 보조 링크는 틸 — 버튼 색으로 "이게 메인 액션인지 카드 안의 보조 액션인지"를 구분.

### 4-9. 인증 배지 (`.pd-certs` / `.pd-cert`) — §5-1에서 상세

### 4-10. 폼 (`.form-box`, 문의하기 페이지)
- 옅은 회색 배경(`--bg-light`) + 상단 2px 네이비 보더로 "박스"임을 표시.
- 인풋/텍스트에어리어는 각진 사각(`border-radius:0`), 포커스 시 보더 컬러만 네이비로 전환(그림자·아웃라인 없음 — 미니멀).
- 라벨은 12px 대문자+letter-spacing(`0.08em`)로 작게, 회색.

### 4-11. 푸터
- 거의 검정에 가까운 네이비(`#050a14`) 배경. 텍스트는 전부 흰색 반투명(`rgba(255,255,255, 0.22~0.42)`) — 불투명도 단계로 위계를 만듦(로고 옆 설명문 0.32, 카피라이트 0.22로 가장 흐림, 컬럼 제목 0.42로 가장 밝음).
- 4열 그리드(브랜드 2fr + 3개 링크 컬럼 1fr씩), 768px 이하에서는 3열로 줄고 브랜드 영역만 전체 폭 차지(`grid-column: 1 / -1`).

## 5. 실제 프롬프트 → 디자인 결정 로그

### 5-1. 인증마크 배지 — 사이즈는 한 번 정하면 사이트 전체 재사용
> 프롬프트: *"우리가 제품소개 페이지에 넣었던 그 인증마크들 알지? 그사이즈로"*

```css
.pd-certs { display:flex; flex-wrap:wrap; gap:14px; }
.pd-cert { width:70px; flex-shrink:0; text-align:center; }
.pd-cert img { height:44px; width:auto; max-width:100%; object-fit:contain; margin:0 auto; }
.pd-cert-label { margin-top:6px; font-size:11px; color:#666; line-height:1.2; }
```
CSS 파일에도 "다른 페이지에서도 재사용" 이라는 주석이 명시적으로 남아있음(1260행). `about.html` 통계 영역을 배지 행으로 교체할 때도 이 규격을 그대로 가져다 씀 — **원칙**: 인증 배지처럼 여러 화면에 반복 등장하는 요소는 페이지마다 새로 사이즈를 잡지 않는다. 개별 상품에서 특정 배지를 숨겨야 할 땐 사이즈를 건드리지 않고 데이터 레벨의 `cert_exclude` 배열로 필터링만 한다(예: 갤러리창은 KS/환경표지 제외).

### 5-2. 제품 이미지 비율 — 원본 비율에 프레임을 맞춘다 (자르지 않는다)
> 프롬프트: *"그림 너무 잘렸다 문 안잘리게해줘"* → *"아니 흰색여백없으면서 안잘리게해줘"* → (3가지 절충안 제시 후) *"다시 바탕화면 그림 2로 해서 거기에 맞춰서 비율 선택해줘"*

- 겪은 문제: 정사각형에 가까운 고정 프레임에 세로로 긴 실제 제품 사진을 `object-fit: cover`로 넣으면 위아래가 잘리거나, 반대로 여백이 생기는 딜레마.
- **최종 해법**: `.pp-thumb { aspect-ratio: 565 / 511; overflow:hidden; }` — 565×511은 실제 업로드 이미지의 원본 픽셀 비율 그대로. 프레임을 이미지에 맞췄지 이미지를 프레임에 맞추지 않음.
- 카드 3개 중 하나만 이미지가 바뀌어도 **나머지 카드도 같은 비율로 통일**해서 그리드가 들쭉날쭉해 보이지 않게 함(*"나머지것들도"*).
- **일반화 원칙**: `object-fit: cover`를 쓰는 모든 카드(제품카드/공지카드 등)에서 이미지가 부자연스럽게 잘린다는 피드백이 오면, 자르는 영역(`object-position`)을 조정하기보다 먼저 **`aspect-ratio` 자체가 실제 이미지 비율과 얼마나 다른지**부터 확인한다.

### 5-3. 배너 텍스트는 미니멀하게 — 코드/스펙 숫자는 배너에서 뺀다
> 프롬프트 예: *"(AL)이건 빼줘"*, *"'총 00종' 이부분은 다 빼줘"*, *"배너에 있는 150mm는 다 빼줘"*, *"규격상세표 밑에 연하게 회색으로 써있는 글씨... 그거 다 없애줘"*

- **원칙**: 제품명 배너(`.pd-h-ko`/`.pd-h-en`)는 "무엇인지"만 크게 보여주고, 스펙 코드·개수·mm 사이즈 같은 세부 정보는 아래 규격상세표(`.spec-table`)로 내린다. 배너에 부가정보가 쌓이면 계속 빼내서 헤드라인을 가볍게 유지 — 이 사이트에서 여러 차례 반복된 패턴.

### 5-4. 갤러리 캡션 — 카테고리명 + 개별명 2줄 포맷
> 프롬프트: *"텍스트에 각 탭이름 추가해줘 ex) 교육시설 엔터하고 이리모현초 이렇게 두줄로"* → *"글줄사이 너무가까워 좀 띄워줘"*

- 마크업: `<span class="ko-only">교육시설<br>이리모현초</span>` — `<br>`로 강제 줄바꿈.
- 스타일: `.home-gal-grid .gal-caption { line-height: 1.7; }` — 기본 `line-height` 없이 `<br>`만 넣으면 두 줄이 붙어 보임. **반드시 `line-height`를 명시적으로 지정해야 함** (body 기본값 1.67em을 물려받길 기대하면 안 됨 — §6 "자주 겪는 버그" 참고).
- **원칙**: 호버 캡션처럼 짧은 텍스트에 계층(카테고리 → 개별 항목)을 표현할 땐 크기·색을 다르게 주지 않고 **줄바꿈 + 여유 있는 line-height**만으로 위계를 만든다 (배지/태그를 추가로 얹지 않는 미니멀 원칙 유지).

### 5-5. 회사연혁 타임라인 — "큰 연도 숫자 + 체크리스트"
> 프롬프트 흐름: *"간격이 너무 띄워져있어... 왼쪽에 파란색 점은 없애줘"* → *"좀더좁혀줘 근데 너무심심하게 그리고 년도별로 좀 나눴으면 좋겠는데.. 좋은디자인없을까"* (AskUserQuestion으로 "큰 연도 숫자 + 체크리스트" 선택) → *"근데 년도밑에 글이 오잖아. 그 글줄만 좀더 띄워줘"*

```css
.tl-year-hd { display:flex; align-items:baseline; gap:14px; margin-bottom:22px; }
.tl-year-num { font-size:30px; font-weight:800; color:var(--navy); }
.tl-year-line { flex:1; height:2px; background:linear-gradient(to right, #1e5e68, rgba(30,94,104,0)); }
.tl-list li { display:flex; gap:9px; padding:9px 0; font-size:14px; }
.tl-check { color:#1e5e68; font-weight:800; font-size:13px; }
```
- 이전 시도(점+세로선 타임라인)를 버리고, **연도를 타이포그래피로 강조**(30px/800) + 우측으로 옅어지는 그라데이션 언더라인 + 담백한 체크리스트로 교체.
- `margin-bottom: 22px`(연도 헤딩 → 리스트 사이)와 `padding: 9px 0`(리스트 항목끼리)이 **서로 다른 속성으로 분리**되어 있음 — "년도밑에 글이 오잖아. 그 글줄만 좀더 띄워줘" 요청이 리스트 항목 간격은 안 건드리고 헤딩-리스트 간격(`margin-bottom`)만 조정해서 해결됨.
- **일반화 원칙**: 리스트형 콘텐츠의 간격을 짤 때는 처음부터 "그룹 헤딩-리스트 간격"과 "리스트 항목 간 간격"을 별개 속성(하나는 그룹 컨테이너의 margin, 하나는 항목의 padding)으로 분리해서 설계한다. 하나의 margin으로 뭉뚱그리면 나중에 "이 부분만 더 띄워줘" 요청이 들어왔을 때 다시 쪼개야 함.

### 5-6. 서브탭(sub-nav-bar) 모바일 — 3열 고정 + 얇은 회색 경계선
CSS 안에 이미 상세한 문제/해법 주석이 남아있어 그대로 인용:

> *"배너 밑 서브탭 — 개수 많으면 줄바꿈되면서 삐뚤빼뚤해 보이던 문제. 한 줄에 3개씩 고정하고 연한 회색 선으로 칸을 나눠서 정돈된 느낌으로. 양끝 탭(1,3번째)도 화면 끝까지 딱 붙게 좌우 패딩 제거, 등장 애니메이션도 꺼서 선이 안 흔들리게 함"*

```css
@media (max-width: 768px) {
  .sub-nav-inner { gap: 0; padding: 0; }
  .sub-nav-bar a {
    flex: 0 0 33.333%; box-sizing: border-box; text-align: center;
    padding: 12px 6px; font-size: 13px; line-height: 1.3; white-space: normal;
    border-right: 1px solid #eee; border-bottom: 1px solid #eee;
    animation: none;
  }
  .sub-nav-bar a:nth-child(3n) { border-right: none; }
}
```
- **원칙**: 탭이 많아질수록 `flex-wrap`으로 자연스럽게 줄바꿈시키기보다, 열 개수를 명시적으로 고정(`flex: 0 0 33.333%`)하고 `nth-child(3n)`로 마지막 열의 보더만 제거하는 쪽이 "삐뚤빼뚤해 보이는" 문제를 근본적으로 없앤다. 개수가 3의 배수가 아니어도 그리드가 안 깨짐.

## 6. 자주 겪는 버그 / 모바일 대응 (CSS 주석에 이미 기록된 실전 트러블슈팅)

이 섹션은 `style.css` 768px 미디어쿼리 안에 실제로 남겨둔 코멘트를 근거로 함 — 다음에 비슷한 레이아웃을 짤 때 같은 삽질을 반복하지 않기 위한 기록.

1. **`<br>` 두 줄 텍스트가 붙어 보임**: `line-height`를 명시하지 않으면 body의 전역 기본값(`1.67em`)을 물려받길 기대하기 쉽지만, 컴포넌트마다 `line-height`가 개별 지정된 경우가 더 많아 실제로는 값이 뒤섞임 → 여러 줄 텍스트를 넣는 컴포넌트는 **항상 `line-height`를 명시적으로 지정**.
2. **표(`.board-table`)가 모바일에서 셀 폭 고정 때문에 안 깨지고 글자가 넘침**: `table-layout: fixed`가 데스크톱에서는 안정적이지만 모바일 좁은 폭에서는 셀이 안 줄어들고 글자가 밀려나옴 → 768px 이하에서 `table-layout: auto`로 전환 + `word-break: keep-all`로 단어 단위 줄바꿈.
3. **가로로 넓은 표(`.proj-board`, `.spec-table`)가 모바일에서 눌리기만 하고 스크롤이 안 됨**: `width:100%`인 표는 좁은 화면에서 그냥 다 눌려버림 → 부모에 `overflow-x:auto` + 표 자체에 `min-width:640px`를 줘서 "표는 원래 크기 유지, 부모가 스크롤" 방식으로 전환. 스크롤 가능하다는 걸 알려주려고 문구 대신 **오른쪽 끝에 흰색 페이드 그라디언트**(`::after`)만 살짝 얹음 — 안내 문구 없이 시각적 신호만.
4. **가운데 정렬 배너 서브텍스트가 2줄이 되면 타이틀과 겹침**: `line-height` 미지정 상태로 body 기본값(1.67em)을 물려받아 줄 간격이 예상보다 넓어져서 발생 → 768px에서 `line-height: 1.35`로 명시 축소 + 좌우 패딩 10px 추가(화면 끝에 텍스트가 딱 붙는 것도 방지).
5. **모바일에서 hover 인터랙션(확대/그림자)이 터치 시 계속 남아있는 느낌**: `.pp-card`처럼 데스크톱에서 hover 시 `scale`+`box-shadow` 주는 카드는 모바일(터치 디바이스)에서 오히려 어색함 → 768px 이하에서 해당 hover 효과를 전부 `none`으로 무효화.

## 7. 다음 프로젝트에 적용할 때

- **색상·폰트는 그대로 재사용하지 말 것**(하나스토리 고유 브랜드) — 새 프로젝트는 새 팔레트로 `:root` 다시 정의. 단, "메인색 1개(구조용) + 포인트색 1개(행동유도용)"로 역할을 나누는 2색 체계 자체는 재사용 가능.
- **컴포넌트 설계 원칙(4번, 재사용 가능)**:
  - 표는 용도별로 클래스를 분리한다(게시판형/정보형/스펙형을 섞지 않음).
  - 카드 이미지는 "여백 있는 이미지=contain, 꽉 채우는 사진=cover"로 구분하고, cover를 쓸 땐 `aspect-ratio`를 실제 이미지에 맞춘다.
  - 배지·태그는 색으로 종류를 구분하지 않고 하나의 톤으로 통일해서 텍스트 내용으로만 구분한다.
- **디자인 결정 원칙(5번, 재사용 가능)**: 반복 요소는 사이즈를 한 곳에서 정하고 전체 재사용 / 이미지는 자르지 말고 프레임을 맞춘다 / 배너는 가볍게, 스펙은 아래로 / 계층은 색보다 줄바꿈+line-height로 / 그룹 간격과 항목 간격을 분리해서 관리 / 탭이 많으면 열 고정+경계선.
- **6번(모바일 버그 노트)은 특히 재사용 가치가 높음** — `line-height` 명시, 넓은 표의 `overflow-x` + `min-width` 조합, hover 효과의 모바일 무효화는 반응형 작업을 할 때마다 반복되는 이슈라 새 프로젝트 시작할 때 미리 체크리스트로 참고.
