# Recipe Recommender (신혼부부 2인 기준)

냉장고 재료 JSON 폴더를 스캔해 **신혼부부(2인)**를 위한 레시피를 추천하고 상세 조리법을 생성하는 skill.

## 필수 규칙 (항상 적용)

1. **재료 폴더 우선 읽기**: 이 skill을 실행할 때마다 **반드시 가장 먼저** `week-4/냉장고재료json폴더/`의 모든 `.json` 파일을 읽고 재료 목록을 파악한다. 사용자가 다른 경로를 명시한 경우만 그 경로를 사용한다.
2. **신혼부부 모드 기본값**:
   - 분량: **2인분 고정** (사용자가 다르게 요청하면 그에 맞춤)
   - 신혼 가정 기준 — 비싸고 흔치 않은 재료/도구 지양, 마트·편의점에서 쉽게 구할 수 있는 추가 재료만 사용
   - 너무 매운 음식 / 너무 자극적인 음식은 피하고, 함께 먹기 좋은 메뉴 우선
   - 한 끼 식사로 균형 잡히도록 단백질·채소가 함께 들어가는 메뉴 가산점
   - 데이트 분위기·기념일·평일 저녁 등 상황을 물어보면 그에 맞춰 조정 (없으면 평일 저녁 기준)
   - 1시간 이내 조리 가능한 메뉴 우선 (퇴근 후 만들 수 있는 수준)
   - 남은 분량은 다음 날 도시락이나 야식으로 응용 가능한 팁을 1줄 이상 포함

## 기본 재료 폴더

기본 경로: `week-4/냉장고재료json폴더/`

사용자가 다른 경로를 지정하면 해당 경로 사용. 폴더의 모든 `.json` 파일이 재료 1개씩.

## 재료 JSON 스키마

```json
{
  "name": "재료명(한글)",
  "nameEn": "Name(영문)",
  "category": "축산물 | 채소 | 유제품 | 곡물 | 해산물 | 과일 | 기타",
  "unit": "개 | 장 | 통 | g | ml ...",
  "averageWeight": 60,
  "weightUnit": "g",
  "calories": 78,
  "nutrition": { "protein": 6.3, "fat": 5.3, "carbs": 0.6, "unit": "g" },
  "storage": { "method": "...", "temperature": "...", "shelfLife": 30, "shelfLifeUnit": "일" },
  "tags": ["..."]
}
```

## 워크플로우

### 1단계: 재료 스캔 (항상 가장 먼저 실행)
- **반드시 먼저** `node scripts/list-ingredients.js week-4/냉장고재료json폴더`로 폴더 요약 확인 (또는 Glob으로 `<폴더>/*.json` 찾고 Read로 모든 파일 읽기)
- 사용자에게 "현재 냉장고에 있는 재료: A, B, C" 요약 표시 (유통기한 짧은 것 강조)
- 재료가 0개면 사용자에게 알리고 종료

### 2단계: 레시피 추천 (신혼부부 2인 기준)
재료 조합을 보고 **3~5개** 레시피 후보를 제시. 각 후보마다:
- 요리명
- 필요한 보유 재료 (몇 개 사용)
- 추가 필요한 재료 (마트에서 쉽게 구할 수 있는지 표시)
- 예상 조리 시간 (퇴근 후 가능한지 ⏱)
- 난이도 (★~★★★★★, 신혼부부 함께 만들기 좋음 표시)
- 한 줄 설명 + 어울리는 상황 (평일 저녁 / 주말 브런치 / 기념일 등)

추천 기준:
1. **재료 활용도**: 보유 재료를 많이 쓰는 요리 우선
2. **신혼부부 적합성**: 2인분 분량 적정, 함께 만들기 즐거운 난이도, 매운맛 과하지 않음
3. **카테고리 다양성**: 한식/양식/중식/일식 다양하게 (한 끼 식사형 + 가벼운 안주형 1개 섞기)
4. **난이도 분포**: 쉬운 것(평일용)부터 도전적인 것(주말용)까지
5. **유통기한**: `shelfLife`가 짧은 재료(예: 토마토 7일)를 우선 소진하는 레시피 가산점
6. **균형식**: 단백질·채소가 한 접시에 같이 들어가는 메뉴 가산점

추천 후 사용자에게 어떤 레시피를 만들지 물어보기. 사용자가 "다 만들어줘"라고 하면 전체 생성.

### 3단계: 상세 레시피 생성
선택된 레시피를 마크다운 파일로 저장. 저장 위치: `week-4/냉장고재료json폴더/recipes/<요리명>.md`

마크다운 템플릿:

```markdown
# {요리명}

> {한 줄 소개 — 신혼부부 데이트/평일 저녁 등 어울리는 상황 명시}

## 정보
- **조리 시간**: {분} 분
- **난이도**: {★~★★★★★}
- **분량**: 2인분 (신혼부부 기준)
- **카테고리**: {한식/양식/...}
- **칼로리(1인분)**: 약 {kcal} kcal
- **추천 상황**: {평일 저녁 / 주말 브런치 / 기념일 / 가벼운 안주 등}

## 재료

### 보유 재료 사용
- {재료}: {수량}{단위}
- ...

### 추가 필요 재료 (마트에서 쉽게 구할 수 있는 것 위주)
- {재료}: {수량}{단위}
- ...

## 조리 순서
1. {단계 1}
2. {단계 2}
...

## 둘이서 함께 만들기 팁
- **역할 분담**: 한 명은 {A}, 한 명은 {B} 동시에 진행하면 시간 단축
- {조리 팁 1}

## 보관 / 다음 날 활용
- {남은 분량 보관법}
- {도시락·야식 응용 아이디어}

## 영양 정보 (1인분 기준 추정)
- 단백질: {g}
- 지방: {g}
- 탄수화물: {g}
```

저장 후 사용자에게 파일 경로와 함께 한눈에 보이는 요약 출력.

## 사용 예시

### 예시 1: 추천만
```
사용자: "냉장고에 뭐 있는지 보고 추천해줘"
→ 폴더 스캔 → 재료 목록 표시 → 3~5개 레시피 후보 제시
```

### 예시 2: 추천 + 생성
```
사용자: "오늘 저녁 뭐 해먹지?"
→ 재료 스캔 → 레시피 후보 제시 → 사용자가 선택 → 마크다운 파일 생성
```

### 예시 3: 특정 재료 위주
```
사용자: "토마토 위주로 추천해줘"
→ 토마토를 메인으로 쓰는 레시피만 후보로 제시
```

### 예시 4: 직접 요청
```
사용자: "오믈렛 레시피 만들어줘"
→ 재료 폴더에서 매칭되는 재료 확인 → 부족한 재료 표시 → 마크다운 생성
```

## 주의사항

- **재료 폴더 먼저 읽기**: skill 호출 시 어떤 요청이든 가장 먼저 `week-4/냉장고재료json폴더/`의 JSON을 모두 읽어 현재 재료를 파악한 뒤 답한다.
- **2인분 고정**: 사용자가 다르게 요청하지 않는 한 신혼부부 기준 2인분으로 계산한다.
- 재료가 부족하면 **추가 필요 재료**에 명시 (절대 생략 금지)
- 마트에서 구하기 어려운 식재료(예: 송로버섯, 캐비어 등)는 신혼부부 일상식 기준에서 제외
- 알레르기/특수 식단 정보는 사용자가 명시한 경우만 반영
- 마크다운 파일 저장 전에 `recipes/` 폴더가 없으면 자동 생성
- 같은 이름의 레시피가 이미 있으면 덮어쓰지 말고 `요리명-2.md` 형식으로 저장

## 헬퍼 스크립트

재료 폴더를 빠르게 요약하려면:

```bash
node scripts/list-ingredients.js week-4/냉장고재료json폴더
```

출력 예시:
```
재료 5개 발견:
- 계란 (축산물, 60g, 30일)
- 토마토 (채소, 150g, 7일) ← 유통기한 짧음
- 양파 (채소, 200g, 30일)
- 치즈 (유제품, 18g, 14일)
- 양배추 (채소, 1000g, 14일)
```
